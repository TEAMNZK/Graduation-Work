# Firestoreの読み書き削減

## 変更内容

- ランキング・履歴のリアルタイム購読を単発取得に変更。
- 同じアカウント・言語の結果をメモリに5分間保持し、待機画面への往復で再取得しない。
- 同時取得の要求は1つにまとめる（開発時のEffect再実行も対象）。
- 結果保存は従来どおり1プレイ1文書。履歴・ランキング用の追加書き込みはしない。
- 保存成功した結果は手元のキャッシュにも反映し、再読込を省く。
- ランキング10件、履歴20件の取得上限を維持。

初回・期限後の表示は各クエリを1回実行します。返る文書数などに応じて課金されるため、「1クエリ＝1読み取り」ではありません。取得0件にも最低課金があり、その他の料金条件は公式料金ページを参照してください。
https://firebase.google.com/docs/firestore/pricing

5分経過だけでは自動取得しません。期限後に待機画面を開いた際に取得します。そのため開きっぱなしの画面では古い記録が残ります。
ページの再読み込み・タブを閉じる操作でメモリキャッシュは消えます。端末・タブ間では共有しません。他端末での本人の記録も次の取得時に反映されます。
保存直後に手元で追加する行の日時は端末の保存完了時刻です。次回取得でFirestoreの正式な日時に置き換わります。Firestore保存は引き続きserverTimestampです。

## 確認

1. Java待機画面を開き、ランキング・履歴が表示されること。
2. 5分以内にプレイして保存し、待機画面へ戻ると自分の新記録が表示されること。
3. 画面を往復しても、初回取得後は同一クエリを再実行しないこと。
4. アカウント切替で他人の履歴を表示しないこと。
5. 5分経過後に待機画面に戻るとサーバーから再取得されること。
6. 1プレイにつきtypingScoresの追加が1件であること。

Firebaseのルール・インデックスの追加変更は不要です。対象はタイピングのランキング・履歴です。他画面のFirebase通信は変更していません。

コミット案：`perf: タイピング記録の購読を単発取得とキャッシュに変更`
